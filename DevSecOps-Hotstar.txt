# DevSecOps Hotstar

## End-to-End AWS EKS CI/CD Setup Guide

This guide configures an Ubuntu EC2 instance as a Jenkins automation host, creates an Amazon EKS cluster with Terraform, and deploys a Hotstar-style application through an integrated DevSecOps pipeline.

---

## 1. Architecture Overview

The environment includes:

- GitHub for source control
- Jenkins for build and deployment orchestration
- SonarQube for static code analysis
- OWASP Dependency-Check for dependency security
- Docker and Docker Scout for image security
- Terraform for AWS infrastructure
- Amazon EKS for Kubernetes workloads
- Amazon S3 for Terraform remote state

The infrastructure and application pipelines should be maintained separately:

| Jenkins Job | Responsibility |
|---|---|
| EKS Provision | Initialize, validate, plan, apply, or destroy Terraform infrastructure |
| HOTSTAR | Build, scan, publish, and deploy the application |

---

## 2. Create the Jenkins EC2 Instance

1. Launch an Ubuntu EC2 instance.
2. Use `t2.large` or a suitable larger instance.
3. Allocate at least 30 GB of storage.
4. Attach an IAM role with only the permissions required for EC2, EKS, IAM, S3, and related resources.
5. Connect to the instance through SSH.

Recommended inbound rules:

| Port | Source | Purpose |
|---:|---|---|
| 22 | Administrator IP | SSH |
| 8080 | Administrator/VPN CIDR | Jenkins |
| 9000 | Administrator/VPN CIDR | SonarQube |
| 3000 | Required application/network CIDR | Application container |

Do not expose Jenkins or SonarQube to the public internet with unrestricted security group rules.

## 3. Install Jenkins and Java

Run the following commands on the EC2 instance:

```bash
sudo apt update -y
sudo apt install -y wget curl gnupg ca-certificates

wget -O - https://packages.adoptium.net/artifactory/api/gpg/key \
  | sudo tee /etc/apt/keyrings/adoptium.asc

echo "deb [signed-by=/etc/apt/keyrings/adoptium.asc] https://packages.adoptium.net/artifactory/deb $(awk -F= '/^VERSION_CODENAME/{print $2}' /etc/os-release) main" \
  | sudo tee /etc/apt/sources.list.d/adoptium.list

sudo apt update -y
sudo apt install -y temurin-17-jdk

curl -fsSL https://pkg.jenkins.io/debian-stable/jenkins.io-2023.key \
  | sudo tee /usr/share/keyrings/jenkins-keyring.asc > /dev/null

echo "deb [signed-by=/usr/share/keyrings/jenkins-keyring.asc] https://pkg.jenkins.io/debian-stable binary/" \
  | sudo tee /etc/apt/sources.list.d/jenkins.list

sudo apt update -y
sudo apt install -y jenkins
sudo systemctl enable --now jenkins
```

Verify the services:

```bash
java --version
jenkins --version
sudo systemctl status jenkins --no-pager
```

Open:

```text
http://<EC2-PUBLIC-IP>:8080
```

Retrieve the initial administrator password:

```bash
sudo cat /var/lib/jenkins/secrets/initialAdminPassword
```

Complete the Jenkins setup wizard and install the recommended plugins.

## 4. Install Docker

```bash
sudo apt update
sudo apt install -y ca-certificates curl gnupg
sudo install -m 0755 -d /etc/apt/keyrings

curl -fsSL https://download.docker.com/linux/ubuntu/gpg \
  | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg

sudo chmod a+r /etc/apt/keyrings/docker.gpg

echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo \"$VERSION_CODENAME\") stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker

sudo usermod -aG docker ubuntu
sudo usermod -aG docker jenkins
sudo systemctl restart jenkins
```

Reconnect to the EC2 instance before testing Docker from the Ubuntu account:

```bash
docker run --rm hello-world
```

Avoid `chmod 777 /var/run/docker.sock` on shared or production hosts. Docker socket access provides effectively unrestricted access to the host.

## 5. Install Terraform

```bash
sudo apt install -y wget gnupg

wget -O- https://apt.releases.hashicorp.com/gpg \
  | sudo gpg --dearmor -o /usr/share/keyrings/hashicorp-archive-keyring.gpg

echo "deb [signed-by=/usr/share/keyrings/hashicorp-archive-keyring.gpg] https://apt.releases.hashicorp.com $(lsb_release -cs) main" \
  | sudo tee /etc/apt/sources.list.d/hashicorp.list

sudo apt update
sudo apt install -y terraform
terraform --version
```

Configure Terraform as a Jenkins tool:

1. Open **Manage Jenkins**.
2. Open **Tools**.
3. Add **Terraform**.
4. Use name `terraform`.
5. Disable automatic installation.
6. Set the installation directory to `/usr/bin/`.

Confirm the executable location:

```bash
which terraform
```

## 11. Configure SonarQube Credentials

In SonarQube:

1. Open **Administration > Security > Users**.
2. Create or select a user token.
3. Give the token a descriptive name.
4. Copy the token once and store it securely.

In Jenkins:

1. Open **Manage Jenkins > Credentials**.
2. Add a **Secret text** credential.
3. Use `sonar-token` as the credential ID.
4. Paste the SonarQube token as the secret.

Then open **Manage Jenkins > System**:

1. Add a SonarQube server.
2. Use name `sonar-server`.
3. Set the SonarQube server URL.
4. Select credential ID `sonar-token`.

Configure a Jenkins webhook in SonarQube:

```text
Name: Jenkins
URL: http://<JENKINS-HOST>:8080/sonarqube-webhook/
Secret: leave empty unless a secret is configured
```

## 13. Create the EKS Provision Pipeline

Create a Jenkins pipeline job named `EKSJOB`.

Add a parameter:

```text
Name: action
Choices:
  apply
  destroy
```

Example pipeline:

```groovy
pipeline {
    agent any

    parameters {
        choice(name: 'action', choices: ['apply', 'destroy'], description: 'Terraform action')
    }

    stages {
        stage('Checkout') {
            steps {
                git branch: 'main',
                    url: 'https://github.com/<OWNER>/<INFRASTRUCTURE-REPOSITORY>.git'
            }
        }

        stage('Terraform Version') {
            steps {
                sh 'terraform --version'
            }
        }

        stage('Terraform Init') {
            steps {
                dir('EKS_TERRAFORM') {
                    sh 'terraform init'
                }
            }
        }

        stage('Terraform Validate') {
            steps {
                dir('EKS_TERRAFORM') {
                    sh 'terraform validate'
                }
            }
        }

        stage('Terraform Plan') {
            steps {
                dir('EKS_TERRAFORM') {
                    sh 'terraform plan'
                }
            }
        }

        stage('Terraform Apply or Destroy') {
            steps {
                dir('EKS_TERRAFORM') {
                    sh "terraform ${action} --auto-approve"
                }
            }
        }
    }
}
```

Before running the pipeline:

- Replace the Git repository URL.
- Replace the S3 backend bucket name.
- Define AWS region and cluster variables.
- Review IAM permissions and Terraform resources.

## 15. Create the HOTSTAR Application Pipeline

Create a Jenkins pipeline job named `HOTSTAR`.

Example pipeline:

```groovy
pipeline {
    agent any

    tools {
        jdk 'jdk17'
        nodejs 'node'
    }

    environment {
        SCANNER_HOME = tool 'sonar-scanner'
        IMAGE = '<REGISTRY>/<ACCOUNT>/hotstar'
        IMAGE_TAG = "${BUILD_NUMBER}"
    }

    stages {
        stage('Checkout') {
            steps {
                git branch: 'main',
                    url: 'https://github.com/<OWNER>/<APPLICATION-REPOSITORY>.git'
            }
        }

        stage('SonarQube Analysis') {
            steps {
                withSonarQubeEnv('sonar-server') {
                    sh '''
                        $SCANNER_HOME/bin/sonar-scanner \
                          -Dsonar.projectName=hotstar \
                          -Dsonar.projectKey=hotstar
                    '''
                }
            }
        }

        stage('Quality Gate') {
            steps {
                waitForQualityGate(
                    abortPipeline: false,
                    credentialsId: 'sonar-token'
                )
            }
        }

        stage('Install Dependencies') {
            steps {
                sh 'npm install'
            }
        }

        stage('OWASP FS Scan') {
            steps {
                dependencyCheck(
                    additionalArguments: '--scan ./ --disableYarnAudit --disableNodeAudit',
                    odcInstallation: 'DP-Check'
                )
                dependencyCheckPublisher pattern: '**/dependency-check-report.xml'
            }
        }

        stage('Docker Build and Push') {
            steps {
                script {
                    withDockerRegistry(
                        credentialsId: 'docker',
                        toolName: 'docker'
                    ) {
                        sh "docker build -t ${IMAGE}:${IMAGE_TAG} ."
                        sh "docker push ${IMAGE}:${IMAGE_TAG}"
                    }
                }
            }
        }

        stage('Docker Scout') {
            steps {
                script {
                    sh "docker-scout quickview ${IMAGE}:${IMAGE_TAG}"
                    sh "docker-scout cves ${IMAGE}:${IMAGE_TAG}"
                    sh "docker-scout recommendations ${IMAGE}:${IMAGE_TAG}"
                }
            }
        }

        stage('Docker Container Validation') {
            steps {
                sh '''
                    docker rm -f hotstar || true
                    docker run -d --name hotstar -p 3000:3000 "${IMAGE}:${IMAGE_TAG}"
                '''
            }
        }

        stage('Deploy to Kubernetes') {
            steps {
                script {
                    dir('K8S') {
                        withKubeConfig(
                            credentialsId: 'k8s',
                            namespace: 'default'
                        ) {
                            sh 'kubectl apply -f deployment.yml'
                            sh 'kubectl apply -f service.yml'
                        }
                    }
                }
            }
        }
    }

    post {
        always {
            sh 'docker rm -f hotstar || true'
        }
    }
}
```

Update the image repository, Docker registry, Git repository, namespace, and Kubernetes manifest names to match the project.

## 16. Store the EKS Kubeconfig in Jenkins

After creating the cluster:

```bash
aws eks update-kubeconfig \
  --name <EKS_CLUSTER_NAME> \
  --region <AWS_REGION>

cat ~/.kube/config
```

Create a Jenkins secret file credential:

| Field | Value |
|---|---|
| Kind | Secret file |
| File | Copy of `~/.kube/config` |
| ID | `k8s` |
| Description | EKS kubeconfig |

Do not commit the kubeconfig to Git or place it in the repository.

## 18. Security and Credential Hygiene

- Rotate any tokens or credentials that may have been committed to Git.
- Remove `secrets.txt` from Git tracking.
- Add kubeconfigs, `.env` files, private keys, and secret text files to `.gitignore`.
- Use Jenkins credentials or a secrets manager.
- Use a scoped IAM role instead of administrator access.
- Use Kubernetes RBAC and a dedicated namespace.
- Pin container versions and digests.
- Review dependency and container scan findings before promotion.
- Restrict Jenkins credential access to authorized jobs and users.
- Remove public SonarQube and Jenkins exposure after setup.

Removing a secret in a new commit does not remove it from Git history. Rotate exposed credentials and purge sensitive history when required.

## 19. Cleanup

Run the Jenkins `EKSJOB` with `destroy`, or destroy Terraform locally:

```bash
cd EKS_TERRAFORM
terraform destroy --auto-approve
```

Also review AWS for:

- EC2 instances
- EKS clusters
- Elastic Load Balancers
- NAT gateways
- Elastic IP addresses
- Security groups
- Unused volumes
- S3 state resources
- Container registry images

Amazon EKS, EC2, load balancers, and NAT gateways can generate ongoing costs.
